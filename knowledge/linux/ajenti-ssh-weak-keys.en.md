# Ajenti — weak SSH keys and allowlisting

**English** | [🌐 Español](ajenti-ssh-weak-keys.md)

## Concept

Ajenti is an administration panel that may expose SSH keys and access rules. Keys generated by Debian with vulnerable OpenSSL (CVE-2008-0166) have reduced entropy and can be regenerated. If the panel also edits `/etc/hosts.allow`, the attacker IP is allowed and the key grants access.

## When it applies

- Ajenti is reachable with weak or reused credentials.
- The panel displays or downloads SSH keys.
- TCP wrappers restrict SSH and the panel edits the allowlist.

## Procedure

1. Access Ajenti and review users and keys.
2. Download the key and check whether it is weak.
3. Add the attacker IP to the SSH allowlist.
4. Connect with the key and escape the restricted shell.

## Commands

```bash
curl -k https://<HOST>:8000/
# Download key from Ajenti
ssh-keygen -y -f key
ssh -i key <USER>@<HOST>
# Allowlist
curl -k -X POST https://<HOST>:8000/api/hosts.allow -d "ip=<IP>"
```

## Variants

- Regenerate weak keys with `g0tmi1k/debian-ssh`.
- Edit the allowlist from another panel.
- Use the key for another user sharing it.

## Limitations

- The panel may require 2FA.
- The key may not be weak.
- SSH may filter through another mechanism.

## Mitigation

- Regenerate SSH keys and use Ed25519.
- Restrict Ajenti and never expose keys.
- Manage access through a bastion, not editable lists.

## Detection

- Key downloads from the panel.
- `hosts.allow` changes outside deployments.
- SSH logins with old keys.
